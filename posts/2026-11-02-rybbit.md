## What Is Rybbit Analytics?

Rybbit covers both web and product analytics, and its [GitHub repository](https://github.com/rybbit-io/rybbit?ref=dailydev) lists web analytics metrics, user journeys, custom events, retention analysis, and error tracking.

### Product Analytics and Session Replay

Rybbit organizes traffic data around sources, mediums, and standard UTM parameters, allowing you to attribute conversions to specific marketing campaigns. The setup moves further into product analytics through custom events, which let you track specific interactions like button clicks, video plays, or form submissions. You combine these events to create goals and conversion funnels. When a visitor lands on a blog post, clicks a pricing link, and completes a signup form, a funnel report calculates the drop-off rate between each step. 

User journeys map the divergent paths people take after landing on a specific page, showing where traffic flows when visitors ignore your primary call to action. Retention tables calculate how many visitors return in the days and weeks following their first session, which helps measure long-term engagement. The platform also compiles user profiles to group actions under a specific identifier, revealing individual behavior patterns. Session replay reconstructs document object model changes to show cursor movement, scrolling, and clicks, giving you a visual record of user frustration. This replay functionality requires the Rybbit Cloud Pro plan.

### Search and Technical Signals

Analytics data explains what happens on your website, but technical signals explain why users might be leaving. Rybbit connects to Google Search Console to provide read access for Rybbit Cloud properties. This integration pulls clicks, impressions, click-through rates, and average search positions directly into the dashboard. Viewing your search performance next to your behavioral metrics reduces the need to switch between platforms to evaluate organic traffic.

The script tracks Core Web Vitals to measure loading performance, interactivity, and visual stability across different devices. Rybbit also includes browser-side JavaScript error capture. When a client-side script fails in a user's browser, the platform logs the syntax error and the environment details. This feature catches frontend bugs that disrupt the user experience, though it functions differently from server-side observability tools that monitor backend application crashes.

## Is Rybbit Cookieless and Privacy-Friendly?

Rybbit describes its default analytics setup as cookieless. That design choice reduces the friction of managing cookie consent banners, but it does not mean the platform collects no identifying data or guarantees automatic compliance with privacy laws. Finalized 2026 ICO guidance confirms that separate data-protection duties apply whenever collected identifiers or related data count as personal data, regardless of whether a traditional cookie is used. 

### What Rybbit Says It Collects

The platform's [Privacy Policy](https://rybbit.com/privacy) states that it collects page URLs, titles, referrers, and query parameters. The system also logs session details, device information, and geographic location derived from the visitor's IP address, while recording UTM parameters for campaign attribution. According to the policy, Rybbit uses raw IP addresses temporarily to determine geolocation without storing them in the database. Consequently, the platform states that it uses anonymous session and user identifiers without relying on cookies.

### Settings That Change the Privacy Picture

The default privacy configuration changes based on how you implement the tracking script. Rybbit generates user IDs by hashing a combination of the visitor's IP address and user agent. This hashed string may be considered personal data under regulations like the GDPR. You can enable a daily salting option that adds a random, rotating value to the hash. This setting strengthens privacy by breaking the identifier every 24 hours, but it prevents accurate unique-user counts and disrupts long-term retention analysis. 

You can enable an optional IP tracking setting that stores visitor IP addresses permanently. The documentation advises against activating this without a legitimate business need and appropriate user consent. If you use the web SDK, calling an `identify()` method attaches specific user traits, such as an email address or account name, to the session. This method persists the identifier in `localStorage`, which behaves similarly to a cookie under privacy regulations and requires corresponding consent mechanisms. 

Path masking applies to standard analytics events to hide sensitive information in URLs, but this protection does not cover every feature. Web Vitals tracking and session replay can retain the original URL, including the full query string. If your application passes password reset tokens, account IDs, or personal emails through URL parameters, the session replay tool will record them unless you explicitly configure URL redaction rules.

## Rybbit Cloud vs. Self-Hosted

Choosing how to deploy Rybbit comes down to an operations trade-off. Managed hosting reduces infrastructure work and provides immediate access to updates, while self-hosting shifts responsibility to your engineering team in exchange for total data control.

### Rybbit Cloud

The managed Cloud version removes the need to provision servers, configure databases, or apply security patches. You create an account, add the tracking snippet to your website, and access the dashboard immediately. This deployment path fits organizations that want to analyze traffic without maintaining backend infrastructure. The Cloud environment scales automatically to handle traffic spikes, and the pricing tiers dictate your feature access and data retention limits. 

### Self-Hosting Rybbit

Self-hosting gives you complete authority over where your data resides, which helps if you have strict data sovereignty requirements. The vendor estimates a 30-to-120-minute setup time, though this serves as a baseline estimate rather than a guarantee. Running a Node.js application alongside a database requires ongoing maintenance, including SSL certificate renewals, version upgrades, and performance tuning. 

Self-hosted installations send anonymous usage telemetry back to the vendor by default. You can disable this data sharing by setting the `DISABLE_TELEMETRY=true` environment variable, which ensures no instance data leaves your server. The self-hosted repository operates under the AGPL-3.0 license. If you plan to modify the code or incorporate it into a larger software product, you must review these license terms, because they dictate how derived works are shared. If you require a managed environment with isolated data, you should evaluate the Enterprise plan, which lists on-premise installation, single sign-on, and white-labeling capabilities.

## Rybbit FAQs: Quick Answers

**Is Rybbit open source?**
Yes, the self-hosted software is available under the AGPL-3.0 license. If you modify the source code, you must adhere to the copyleft requirements of this license.

**Does its default setup use cookies?**
Rybbit operates without cookies by default, using hashed combinations of IP addresses and user agents. You can manually implement persistent local storage by using the SDK's optional identification methods. 

**Does it support session replay?**
Yes, session replay is available on the Rybbit Cloud Pro plan. It records DOM changes to recreate user sessions visually. 

**Does it connect to Google Search Console?**
Rybbit provides read-oriented Google Search Console access for properties connected to Rybbit Cloud. This pulls clicks, impressions, and average positions into the analytics dashboard. 

**Can it be self-hosted?**
Yes. Self-hosting requires managing your own server infrastructure, database, and software updates. You must manually disable the default usage telemetry if you want to prevent instance data from pinging the vendor. 

**Does it offer white-labeling?**
White-labeling is available on the custom-priced Enterprise plan, alongside single sign-on and dedicated isolated instances.

**Is it automatically compliant with privacy laws?**
No analytics setup guarantees automatic compliance. While the cookieless default reduces banner friction, you must still manage consent if you enable optional IP tracking, use the `identify()` method, or capture personal data within URL query strings during session replays.
